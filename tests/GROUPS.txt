# The test groups of this project - one group per pytest invocation.
#
# WHY ONE BY ONE: tests/unit/services, tests/unit/cogs and tests/unit/utils have
# no __init__.py but are named like the real packages services/, cogs/, utils/.
# In ONE shared pytest run they shadow those, and collection aborts:
#   pytest tests/unit/  -> 79 collection errors, not a single test runs
#   pytest tests/       -> 18 collection errors, not a single test runs
# Both measured on 2026-09-17. --import-mode=importlib does not fix it, and three
# retrofitted __init__.py make it worse, 54 errors (reverted).
#
# This file is the ONLY source of the group list. The CI workflows read it, so
# no copies drift apart. tests/spec/test_z10_group_list.py makes sure every
# test file lies in exactly one group - otherwise a new file would silently
# never run.
#
